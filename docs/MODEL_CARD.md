# Model card — online-zscore-v1

![Feature pipeline](assets/05-feature-and-model-flow.svg)

## Purpose and limits

Flag unusual service telemetry for **human review**, not a proven outage or security diagnosis. Dataset and ground truth are generated by the simulator.

## Default streaming detector

- Inputs: log1p(latency_ms), CPU fraction, error_rate, log1p(rps).
- Separate Welford mean/variance per service; variance floor of 0.04.
- Warmup of 25 normal observations per service.
- Score: maximum absolute feature z-score; alert threshold 3.6.
- Leading deviating feature included as an investigation reason.
- Flagged outliers are excluded from normal baseline updates.
- State lives in worker memory; it is not durable across restarts.

## Optional Isolation Forest experiment

Run: python -m src.models.train --samples 4000

Train on normal-only examples from the chronologically earlier 75% of seeded synthetic events; test on remaining 25%. The model and synthetic evaluation JSON are saved to ignored local artifacts. It is **not** loaded by the Kafka worker.

## Validation plan

Compare synthetic precision, recall, false alarm rate and alert prevalence across seeds and injection rates. Add chronological drift, seasonal patterns and baselines. Validate on an authorized real-world labelled dataset before any operational use.

## Risks

Concept drift, seasonal change, batch effects, untrustworthy labels, warmup false negatives, alert fatigue, noisy low-variance features and adversarial inputs are unaddressed. Educational statistical baseline only.
