# Reproducible streaming performance plan

## Source and limits

All data generated by this repository is synthetic. A successful integration smoke validates correctness of the broker-to-database path but **does not** measure a sustained rate or establish production accuracy.

## Load producer

With Docker running locally:

~~~bash
python -m scripts.kafka_load --events 1000 --rate 50 --seed 42
python -m scripts.kafka_load --events 5000 --rate 100 --seed 42
~~~

The command prints attempted event count, broker acknowledgements and p50/p95 broker delivery latency. It does **not** measure the worker/SQL/API processing rate. Record CPU/RAM, OS, image versions, partitions, producer rate, consumer count, storage type and run date.

## Full-stack protocol

1. Start local Compose with known topic and empty demo volumes.
2. Warm the model and Kafka broker.
3. Generate a fixed-size, fixed-seed synthetic load at a controlled target rate.
4. Compare Kafka broker delivery acknowledgements with SQL persisted event IDs and consumer group offsets.
5. Export Prometheus worker counters and end-to-end metrics from the API, noting any clock offsets.
6. Repeat for 50/100/250/500 events/sec, in at least three independent runs.
7. Report accepted, rejected, persisted, duplicate, missing and DLQ counts.
8. Evaluate p50/p95/p99 per stage and include median/min/max across repeats.
9. Restart the worker and verify persisted baseline recovery and replay deduplication.
10. Test sustained 30-minute steady state, broker interruption and DB interruption separately.

## Interpreting metrics

- Producer acknowledged/sec: Kafka ack throughput.
- Worker processed/sec: Prometheus persisted event counter.
- SQL events/sec: count within a defined storage-time window.
- End-to-end event latency: event timestamp → SQL write (requires clock discipline).
- Worker processing_ms: anomaly calculation and initial database commit, excluding the subsequent timing-record update.
- Consumer lag: query actual Kafka consumer group offsets, **not** inferred from SQL counts.

Compare the 2026-10-28 CI synthetic offline number only with similarly configured runs; it is **not** a target SLA. Isolation Forest evaluation from synthetic labels is not live incident-detection accuracy.

## No fabricated benchmark results

This document specifies an experimental protocol. It does not contain invented throughput improvements, server capacity, external incident accuracy or production SLOs.
